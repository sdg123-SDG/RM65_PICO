# vr_teleop RM65 实机试验

试验区已经把 PICO 输入、头部朝向标定、vr_teleop 仿真及 IK 接到 RM65 实时发送器。每次实机启动先以 10% 关节速度回到 `logs/real/taught_pose.json` 中最近一次手动示教姿态，连续三次反馈确认到位后才启用 PICO 控制；没有有效示教姿态或回位未确认时，遥操不会启动。左手侧键按一次开启跟随、再按一次停止。右扳机模拟量映射到 RM65 `set_gripper_position` 的开口量 1–1000（1 为完全闭合，1000 为完全张开）：松开发送完全张开，按得越深闭合越多，按到底为 1。位置命令采用非阻塞发送并合并尚未发送的旧目标；真实夹爪的连续跟随效果仍需实机确认。

在本目录运行 `start_real_trial.bat`。默认地址来自 `config/sim_real_bridge.local.json`，视角前方映射为 `+X`，位置比例为 0.5；Head 和左手控制器数据需要有效。终端中的 `[real bridge]` 显示当前状态和原因，试验日志位于本目录的 `logs/real`，复用的独立保护进程日志位于原项目 `logs/real`。

独立连接发送夹取及松开命令后，操作者确认实体夹爪均有动作；右扳机重复切换和两种状态回包中的夹爪回执混写恢复已用本机模拟控制器检查，尚未在实机遥操中验证。19:17 实机遥操期间夹爪回执混入 joint_state，随后控制器又返回 JSON 解析错误，发送器退出且停稳未获确认；保护进程的停止命令也未获确认。退出后四次只读关节采样基本稳定、arm_err/sys_err 均为 0，但不能倒推停稳过程成功。控制器解析错误的根因仍未排除。双连接试验发现控制器向两个连接广播回复，不能依靠额外连接隔离夹爪回执。右扳机依据右控制器输入包的新鲜度读取，不依赖左手或右手姿态跟踪。控制箱之前发生重启的原因仍未知。

模型映射记录及只读核查结果保留在 `model_alignment_audit.json` 和 `hardware_preflight_report.json`。当前模型捏合点与控制器 Arm_Tip 有约 173.6 mm 偏移，实体夹爪尖端尚未标定。`start_loopback.bat` 用于只连接本机模拟控制器；`readonly_preflight.bat` 可进行只读检查。
