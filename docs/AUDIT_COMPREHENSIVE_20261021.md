# RM65 / PICO 综合离线审查

日期：2026-10-21。范围：latest_bridge.py、PICO 模型/输入入口、原生状态采样、CLI、退出保护、历史现场记录和回归测试。本轮未连接、使能或运动实体机械臂。修改前快照：audit/comprehensive_20261021_180833。

结论：此前修复偏重单个报错，遗漏了并发、时间基准和生命周期之间的影响。本轮确认并修复以下缺陷；离线通过不等于实体连续遥操验收。

| 问题 | 影响 | 当前修正及验证 |
|---|---|---|
| 粗粒度时钟与追赶发送 | 历史现场运动帧最短约 1–3 ms，调度值 20 ms 不代表实际周期 | perf_counter 高精度调度，写入完成后至少等待 20 ms，不追赶补帧；回环记录验证相邻发送间隔至少 19 ms（测量容差） |
| 原生采样器回写旧缓存 | 新关节状态可能被旧 RPC 结果覆盖，反馈年龄与数据不同步 | 通信模块维护自身反馈快照；原生 fetch_arm_state 只读快照，不再写信箱或模型；回归验证不会倒退，外部修改返回数组不污染内部数据 |
| 保持期间重新握持 | 虚拟目标继续推进，重新跟随的相对起点可能错误 | 同时阻止模型和硬件推进；稳定保持之后必须观察到有效的实际 Grip 释放，才能重新取相对起点 |
| 限幅时内部速度失真 | 实际指令未推进，却保留计划推进的速度 | 以实际发送目标减前一目标更新速度；限幅保持帧对应零推进速度 |
| CLI stop/pause/resume 绕过新版 | 原生 RPC 被拒绝，终端提示与实际暂停可能不一致 | 绑定到当前输出模块；stop/pause 锁定并撤销目标，resume 仅解除锁定，仍需释放再握持，不自动运动 |
| 轴使能/错误只记录 | 即使收到轴异常也可能继续输出 | 对收到的六轴使能/错误回复校验长度和值；禁用轴、错误标志或畸形回复明确报错 |
| 拼接 JSON 不兼容 | 原生接收器能处理的两个相邻对象被新版误判 | 恢复按 raw_decode 分割对象；控制器实际文本错误仍记录并触发暂停，不当作有效反馈 |
| 接收处理无单次预算 | 大量回包可能占住通信线程 | 单次最多读取 16 KiB，解析最多 64 对象且预算约 3 ms，保留剩余内容到下轮 |
| 同步写盘刷新 | 磁盘延迟占用发送线程 | 有界独立日志线程；队列溢出/写盘错误成为可见故障；阻塞磁盘测试验证 enqueue 不被磁盘拖住且记录顺序完整 |
| 重复启用通信线程 | 原线程停止后复用 socket/事件可能启动无效或重复工作线程 | 同一 transport 禁止二次 start，关闭后需新会话 |
| 保护恢复重复执行 | 心跳持续异常时可能反复发恢复命令 | 一个 guard 会话仅执行一次原生恢复流程，内部连接尝试仍由原生流程管理；回归验证多次 watch 调用只有一次恢复 |
| PID 复用和退出记录复用 | 旧记录可能错误抑制保护 | 心跳和退出记录均包含随机会话标识；校验 PID、地址、标识、时间和确认状态；原子写记录，失败仍执行基础清理 |
| 保护日志不持久 | 主终端关闭后丢失接管证据 | 独立 guard_<pid>_<token>.log，保留正常退出/恢复结果 |
| 测试与现场日志混存 | 最新文件可能来自假控制器，误当现场证据 | 回环测试日志改为临时目录；真实日志新增 peer 标识；历史文件保留不删除 |

## 前几次故障的统一证据

机器可读台账：audit/comprehensive_event_ledger_20261021.json。历史最大帧间隔跨越松手/保持区间，不能直接解释为运动中的网络延迟。

- 17:34：25 帧，set_arm_stop 被确认后反馈消失。用户现场确认灯灭重亮/掉使能恢复；软件证据不足以确定控制器或电源重启的原因。
- 17:51：36 帧，控制器文本 `2, '}' expected near end of file`，触发原接收器退出。
- 17:55：297 帧，完成回包未匹配且 1 秒保持期限过短；已在前续修正。
- 17:58：576 帧、3 次保持确认成功后，再收到控制器文本解析错误。
- 18:03：713 帧、5 次保持确认成功后，丢失只读回复导致查询槽堵住；此前已经补只读超时释放/重试，不重发运动命令。

历史日志里实际最短发送间隔分别达到约 6.0、2.9、1.0、2.0 ms。比此前仅从粗粒度 monotonic 看到的 15 ms 更严重。突发发送是控制器解析错误的合理嫌疑，但没有固件抓包/控制器日志，不能称为已证明因果关系。

## 仍未解决或未验证

1. 控制箱重启根因和控制器文本解析错误根因均未被证明。需要控制器事件记录或实际双向通信证据，离线假控制器不能模拟其全部固件行为。
2. Windows 仍非硬实时；当前发送间隔设下限、取消追赶，并不保证恰好 50 Hz。网络拥塞/部分发送时不自动继续透传。
3. 运动时该机 joint_state 只提供关节/arm_err，不含新鲜 sys_err、使能和位姿；不能称所有内部状态都在实时完整监测。没有支持无 CANFD 回包的其他控制器版本。
4. 协议缺少请求序号，迟到的匿名轨迹完成事件不能获得强身份匹配。当前限定在独占保持窗口内接收，并额外要求目标附近的连续稳定反馈；这仍需实际固件验证。
5. 离散速度变化请求限制不等于经过认证的连续加速度/冲击限制；安全反馈窗口触发时可立即冻结目标。独立仿真目标可能领先实机，不能将最新目标年龄当作实体跟随误差。
6. 方向 +X/-X、夹爪、手动基准仍未做本轮现场验收。没有自动回零或自动回基准；没有重新启动实体遥操来反复试错。
