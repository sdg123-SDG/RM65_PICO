## 指令及实测结果

原 CLI 执行前的 MDH 关节角（度）：

`[0.001, 0.111, -0.277, -0.089, -0.189, 10.780]`

仅 J1 目标增加 0.1°，其余保持该次回读值，显式速度 1%：

```text
movej 0.101 0.111 -0.277 -0.089 -0.189 10.780 1
```

发出后原 CLI 回读：

`[0.098, 0.114, -0.276, -0.090, -0.189, 10.780]`，`arm_err=0`、`sys_err=0`。

J1 实测变化约 +0.097°，接近 +0.1° 目标。其他轴读数变化约 0.001～0.003°，不据此声称完全无运动或均为噪声。

之后输入 quit，未发送回程命令。退出过程有延迟，最终原主进程及守护进程均已结束、TCP 连接释放。退出终端状态为 1，未拿到完整退出原因，不把该异常宣称为已解决。

退出后另开只读连接，3 次原始控制器 J1 回读依次为 0.097°、0.096°、0.097°，错误均为 0。没有进一步运动指令。

## 能证明与不能证明的事

- 已证明：当前配置下，原 CLI → RealArm.Movej_Cmd → 原 JSON 通路能执行微小 J1 关节运动。
- 未证明：任意笛卡尔方向可达、Movep_CANFD 可正常持续跟随、PICO 映射正确、松手停止距离可靠，或新遥操适配已通过实机验收。
- 不能再将所有“不动”笼统归因于伸直姿态；原版能动与新增遥操被本地 IK 拦截需要分别诊断。
- 原 CLI status 中 collision、gripper 等部分字段来自本地对象。此前直接协议查询的 collision_stage=0、get_gripper_state 超时仍是独立事实，不能用 CLI 显示的 collision=1 / gripper=0 覆盖。

下一阶段应以这条已验证的原生运动通路为基线，最小化接入 PICO；不能把本次 J1 测试当作已验证笛卡尔遥操。
