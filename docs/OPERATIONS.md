# 操作手册

## 开始与退出

双击 start.bat：T=遥操、J=摇杆、S=仅服务、D=输入诊断、V=场景。一次只运行一个模式；遥操与诊断不要同时开。

服务与仿真一起启动。关闭仿真窗口，或在启动终端按 Ctrl+C，会停止这两个进程。强行从任务管理器结束启动器可能来不及执行清理，优先正常退出。

## 遥操：左手柄

| 输入 | 功能 |
|---|---|
| 侧面 Grip 握持键按住 | 相对当前起点跟随 |
| 松开 Grip | 停止保持，下次按住重新取起点 |
| 食指扳机 | 夹爪开合 |
| Grip 松开时，按下左摇杆本体 | 把手柄当时的水平指向设为前方，显示 manual forward |
| Grip 松开时，按 X | 清除手动前方，恢复头显水平朝向，需有效 Head Tracking |
| 左菜单键 | 暂停该次运动；松开 Grip 再开始 |

“按下摇杆本体”：拇指放在左摇杆顶端，**沿摇杆轴线向手柄内部按一下，再松开**，像按按钮。不是推摇杆。若没有正常按钮手感，勿强行施力。

建议初次使用手动前方：松开 Grip，水平指向想作为前方的方向，按一下摇杆本体，看到 manual forward，再按住 Grip 移动。松开后可把手收回舒适位置，再按 Grip 重新取起点，不会直接跳回原位。

手动前方仅在本次 Python 进程内有效，不写跨场地校准文件。换站位/房间、XR 重新居中或重启后应重设。它只校准水平朝向，竖直保持 XR 的重力轴，不用手推“向上”来推算竖直轴。

自动模式：按 X 后，开启 Head Tracking 并面向工作区；每次 Grip 开始采集头部水平朝向，按住期间冻结。缺少头部数据则等待，需恢复数据或手动设前方。

## 坐标与运动方式

默认 frame=robot：红色 +X=前方，绿色 -Y=右方，蓝色 +Z=上方，固定在机器人底座。旋转鼠标观察视角不会改变控制方向；黄色球是 TCP 目标。

默认 mode=position，只跟随位置、保持腕部朝向。转手腕不会自动转夹爪。mode=pose 开启姿态跟随，但尚未完成实际头显的全工作空间验证，先小范围使用。

默认位移倍率 1、末端速度上限 0.06 m/s；快速移动手柄会造成末端滞后。IK、碰撞、关节限位与工作空间限制也影响轨迹，不要把目标黄点当成已经到达的位置。

输入约 0.25 s 不刷新会停止；大幅位置跳变也会要求释放 Grip 再启用。

## 摇杆

左摇杆前后/左右对应前后/左右；Y=升高，X=降低；松杆并松开 X/Y 停住；食指扳机控制夹爪。

仓库启动器默认底座坐标。直接运行旧入口 scripts/jog_rm65_mujoco.py 的默认值为 view；需要一致时显式加 --frame robot。

## 分轴确认

按 Grip，小幅向前 2–3 cm，松开；再分别向右、向上。观察末端相对于底座红/绿/蓝方向的运动。若偏斜，保留录制，记录“实际手势及时间段”，区分输入映射、速度滞后和 IK 偏差。一次混合手势不能证明方向精度。

## 录制与回放

遥操自动将输入、Grip、头部数据、映射、目标/实际 TCP 与关节写入 logs/xr/*.jsonl，默认不上传。真实轨迹可能反映个人空间，分享前检查。

~~~powershell
# 关闭实时模式后，带窗口回放，不初始化 XR SDK：
.\.venv\Scripts\python.exe scripts\teleop_rm65_xrt.py --replay .\logs\xr\你的记录.jsonl
# 无窗口：
.\.venv\Scripts\python.exe scripts\teleop_rm65_xrt.py --replay .\logs\xr\你的记录.jsonl --headless
# 分析：
.\.venv\Scripts\python.exe scripts\analyze_xr_recording.py .\logs\xr\你的记录.jsonl
~~~

回放使用录制的控制参数，命令行可覆盖。记录没有完整嵌入场景或任意起始状态，回放从默认初始姿态开始；跨场景/中途开始记录不能保证重建相同物理结果。
