# PICO → 仿真模型 → RM65 真机

2026-10-21，本页是 `start_real.bat` 当前实现；旧 `REAL_PICO.md`、`REAL_PICO_V2.md` 保留作历史记录，不再是启动配置说明。

## 控制链路

PICO 左手柄位移 → 原有坐标映射 → 原生 MuJoCo `Rm65ExtArm.Movep_CANFD` / IK → 仿真六轴关节目标 → 原版 `RealArm.Movej_CANFD` → 控制器。

真机输出现在在 PICO 控制线程内同步调用原版关节 API：与原版滑条一样，使用 `RealArm.Movej_CANFD` → `JsonMotionPolicy.canfd_deg` → `RealPlant.canfd` 的 CANFD/JSON 路径，等待该调用返回后再读下一拍。原版 UI 滑条实现位于 `vdo-rm65b/simu/session.py::_drive_from_ui`：它以 20 ms 为最短下发间隔、每帧最多 8°，再调用 `arm.set_q`；桥接按同一 CANFD 请求/应答路径下发，保留更严格的“指令与实测最多相差 2°”边界。移除了先前增加的 5°/秒限速、无应答旁路发送和 0.1 秒预延迟。控制器/网络响应较慢时，PICO 控制循环自然放慢，不再让独立发送线程把历史点无限追在后面。

松开 Grip、追踪失效、菜单或退出会丢弃待发点并走原版保持流程；重新按住不补放上次动作，本地模型按原流程重新对齐实测姿态。磁盘记录仅用于分析，不会自动重放到真机。若真机反馈落后，最多在 2°命令差处等待反馈，保留当前队首；待发点年龄超过 `max_replay_lag_s`（默认 0.5 秒）则停止，避免旧轨迹延迟执行。`replay_delay_s` 默认 0，仅为兼容配置保留，不再增加预延迟。

没有把 PICO 笛卡尔位姿直接发给真机，没有再建独立 IK，也没有替换原版 RealPlant。仿真与真机分开保存关节命令，真机反馈只更新状态信箱，不覆盖遥操中的模型。原版 J2/J3/J5 的符号转换仅在原有 RealPlant 边界执行一次。

桥接入口采用仿真重力补偿，并补偿机械臂整个模型子树（含转接件、相机等负载），避免把模型的被动下垂当作手柄命令发给真机；桌子和木块仍保留重力。这只修改本地物理模型，不修改真机的重力/动力学参数。松开 Grip、输出保持完成后，本地模型才重新对齐实测关节并清掉本地六轴速度。

启动时只读真机关节，把本地模型对齐至该姿态。不回零、不移动到仿真 home、不自动使能，也不发送张开/闭合指令。原版 `launch_rm65_box_real.py` 文件保持不变；底层新增可选桥接参数和模型显示分离钩子，默认原生调用不启用这些桥接参数。Windows 保护进程另有兼容修复。

## 启动

先退出原版真机 CLI、旧遥操和其他控制进程，确保没有人拖滑条或发送其他运动。启动器检测已有控制器连接会拒绝启动，不会杀死它们。

```powershell
Set-Location E:\SDG-VLA\RM65_PICO
.\start_real.bat -Check
.\start_real.bat
```

`-Check` 仅检查本地模型/配置，不连接机器人或启动 PICO 服务。安装/补丁更新使用 `setup_vdo.ps1`，或已准备好依赖时运行 `.\.venv\Scripts\python.exe scripts\prepare_vdo.py`。

如果现场确认操作者前方对应机器臂底座 **−X**，启动用：

```powershell
.\start_real.bat -Forward -X
```

默认仍是 +X；不要仅凭画面相机朝向判断底座方向。这里选择的是底座坐标下的操作者前方，手柄前方仍需以下步骤建立。

1. 保持现场有人，检查工作区、线缆、夹爪内外无人，急停可立即触及。首次试验只做很小的水平位移，不自动改变初始关节姿态。
2. 头显与电脑同一可互访网络，打开 XRoboToolkit，选择电脑实际网络 IP，等待 WORKING，启用 Head Tracking、Controller Tracking、Send。
3. 松开左手 Grip 和食指扳机。手柄水平指向希望作为前方的方向，用拇指将左摇杆本体垂直按进去一下，再松开；不是推摇杆。应出现 `manual forward`。
4. 按住左手 Grip 后，先只移动手柄几毫米，观察仿真模型与真机。默认倍率 0.3，手移动 10 mm，模型目标为 3 mm。检查前/右/上是否对应；不对应立即松开，勿靠加大动作试探。
5. 松开 Grip 停止跟随，并请求原版退出透传/保持。再次按住会建立新的相对位移参考。无额外 `pico arm` 命令。菜单、追踪超时、控制器错误、过大关节差等会停止跟随。
6. 正常退出输入 `quit`，等待进程完成清理。软件保持不是物理急停，也不能保证零延时；失控或保持失败时使用现场急停。不要强杀进程作为正常停机手段。

真机桥接关闭了仿真左侧滑条面板，防止它与 PICO 抢同一个模型。不要同时执行 CLI/HTTP 的运动命令；本入口 HTTP 默认关闭。

## 夹爪

2026-10-21 应答修复：夹爪请求现在只接收对应命令的结果，不再把共用 TCP 里其他运动的应答当作夹爪结果。失败时终端及 `logs/real/bridge_error.json` 保留请求、原始应答/异常和跳过的消息；不自动重试，不将超时作为成功。该修复覆盖一类应答错配，不能证明此前那次失败就是错配或已经恢复真实夹爪控制。

若要先单独验收机械臂链路，可明确选择禁用真实夹爪输出（不是自动降级）：

```powershell
.\start_real.bat -NoGripper
# 前方已确认对应底座 -X 时：
.\start_real.bat -NoGripper -Forward -X
```

该模式中食指扳机不发任何真实夹爪命令；不要用于依赖夹爪抓紧物体的操作。默认不加此参数时仍启用扳机控制，夹爪结果未确认仍会停止整条桥接。此问题尚无实机修复验收结论。

不查询、不同步真机夹爪开口。画面初始张开只是命令预览，不代表真实开口。首次必须释放扳机，之后扳机变化才下发夹爪指令：松开方向为张开、扣下方向为闭合，独立于 Grip。重连/追踪失效后也需先释放扳机。

调用的是 `set_gripper_position`，非阻塞，范围 1–1000；画面标注 `PICO command`，不是实测。若控制器不支持该协议或未确认应答，桥接报错停止，不会把超时当作成功。此接口本次只用假控制器验证，尚未做真实夹爪验收。初次试扳机前务必清空夹爪工作区。

## 限幅与诊断

### 11:17 会话：状态显示导致线程死锁

现场表现为只有第一条 SDK_DIAG，随后没有追踪更新，退出时报 `PICO worker has not stopped`。发现 `PicoEeServo._loop` 在持有状态锁时调用 `status_suffix`，后者新增了模型位置读取，需要模型数据锁；画面线程则持有模型数据锁再读取状态锁，形成锁顺序反转。已将状态文本及模型统计计算移到状态锁之外，状态锁内只做字符串赋值。

新增离线并发回归：原代码在受控线程交错下稳定复现互等，修复后同一测试通过且正常退出；另用假追踪、真实模型、假控制器输出与并发画面读状态检查持续运行及退出。测试不连接真实设备。这能确认该软件死锁的修复，不等于 PICO/真机现场联动已经验收。没有改变运动参数、原版真机入口或添加新的操作模式。

2026-10-21 第二次现场日志：`sent_frames=107` 只代表本地发送，录制中模型实际末端有约 15.8 mm 运动，但没有足够记录证明真实关节跟随；随后保持请求未获确认。修复了 `movej` 保持请求可能误收积压 `joint_state` 的问题，保留原始应答/异常；未移除保持确认或提高限幅。此修复尚未现场验收，不能据此宣称真机已经能动。

状态现在分别显示 `SIM_move`（模型末端相对启动位置，mm）和 `REAL_joint_move`（真机实测关节相对启动位置的最大变化，度），不再把发送帧数当作执行确认。录制每帧新增 `bridge`，包含实测/模型/已发关节和反馈年龄。若持续有至少 0.05° 的待跟随目标，而实测关节 1 秒未变化 0.01°，停止输出并报 `NO REAL JOINT RESPONSE`；不以加大动作或放宽限制来强迫真机运动。该检测依赖反馈精度，不替代物理急停。

配置在 `config/sim_real_bridge.example.json`，个人配置放 `config/sim_real_bridge.local.json`，不使用历史 `real_pico.local.json`。

示例配置默认末端目标速度 0.01 m/s、倍率 0.3；本机个人配置保留用户设置 0.08 m/s、倍率 0.8。`max_joint_step_deg` 配置上限为 10°，实际每帧按原版 UI 滑条限制到最多 8°；不再叠加真机 5°/秒人为限速。发送与反馈检查在同一 PICO 控制循环执行，关节输出频率由原生请求/应答耗时决定，不再承诺固定 20 ms。真机命令与实测差接近 2°时，暂缓下发并等反馈追上；追踪失效会取消待发点并保持，不回放过时动作。反馈超时 0.5 秒、待发点过期 0.5 秒或真机关节 1 秒内没有可见响应仍会停止。已按用户要求移除启动点周围 3 cm 的试验半径限制。

以上是软件限幅，不是经过认证的安全功能；不是严格实时速度保证，也没有新增真机碰撞检测。读数错误为零不等于工作区安全；此前采集的控制器碰撞等级为 0，不能宣称已启用硬件碰撞保护。

状态中的 `sent_frames` 是原生 API 返回成功的关节帧数，不等于机械臂已经执行；实际运动看后续实测关节反馈。`sim_real_gap` 是仿真与最新实测关节差；发送端单独限制“已发指令—实测”差不超过 2°。`queue` 是尚未完成的轨迹点数，`replay_lag` 是队首帧年龄，正常锁步时应接近 0。近伸直/奇异姿态向上可能不可达；原生 IK 长时间不进展会报错，不会自动弯臂或回零。

每次连接模式启动都会打印并创建 `logs/real/trajectory_日期时间.jsonl`：`simulation` 记录仿真轨迹点，`sent` 记录原生 API 返回成功的目标角度及调用前可见的真机反馈，二者用 `seq` 对应；当真机反馈不足时同一目标可能等待数拍。API 返回成功不等于物理执行完成，实际运动以之后的关节反馈为准；停止时仍执行原版保持确认流程。`discard` 记录取消点数，`fault` 记录错误。原 `logs/xr` 中的逐帧手柄、仿真、反馈记录仍保留，并增加队列统计。

异常摘要保存到 `logs/real/bridge_error.json`，会话录制在 `logs` 下。出现错误后先确认真机停稳、工作区与初始姿态，再重启；不要反复按 Grip 试探。

## 本次验证范围

真实的新版 MuJoCo 模型 + 原版 RealArm/RealPlant + 假 TCP 控制器离线测试：启动对齐、不发送初始运动/夹爪、六方向调用原有仿真 IK、只输出关节帧、关节符号仅转换一次、反馈不覆盖模型、Grip/追踪失效、夹爪释放门槛、超时/偏差/发送失败拒绝继续输出。

六方向离线样例：手柄目标 8 mm，倍率 0.3，模型指令末端约 2.36–2.38 mm，横向误差 <0.03 mm。这是指定初始姿态下的离线结果，不代表真机精度或全工作空间性能。

另检查了用于输出关节的模型实际物理轨迹：最终同向位移约 2.29–2.40 mm，整个采样过程的最大横向偏移 <0.41 mm。关闭模型重力补偿的对照样例出现约 14 mm 下垂，因此不能仅以 IK 指令正确作为桥接通过的依据。

这版桥接尚未通过 PICO + 真机联动现场验收。本次开发没有自动启动真机跟随，也没有下发真实夹爪指令。历史原版 J1 +0.1° 试动仅证明原版控制通路，见 [原版测试记录](ORIGINAL_REAL_TEST.md)。
